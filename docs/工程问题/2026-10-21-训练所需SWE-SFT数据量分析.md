# 训练所需 SWE SFT 数据量分析（证据版）

日期：2026-10-21。范围：只读核证项目内训练方案与工厂实测收据，换算数据量需求；不调用教师、不启动训练。

## 0. 一句话结论

**pilot 需要 200–500 条合格 episode（训练方案自定），按工厂实测转化率折算为约 470–1,200 道 SWE 任务、约 3.0–7.5 亿教师 prompt token；而本地样本只剩 81 道题，最多产出约 34 条样本——连 pilot 下限的 1/5 都不够。要完成训练任务必须先扩题库。**

**并入 LCB(L) 池后的 Pilot 总量：推荐 500 条 = 400 LCB + 100 SWE（与[用量复核](../../docs/2026-10-19-SFT用量复核与阶段配额.md) §5 首轮配额一致）；合计约 3.5M 序列 token、1.4M 监督 token、31 个 update，教师约 1.53 亿 prompt token。LCB 侧题源够（500 ≤ 880 上限），瓶颈仍是 SWE 侧：100 条需约 282 道任务 > 本地剩余 81 道。详见 §6。**

### 3.3 验证集

按[用量复核](../../docs/2026-10-19-SFT用量复核与阶段配额.md)规则须留独立验证任务（家族级隔离，建议 15–20%），上表任务数需再乘约 1.2。

## 4. 两个必须先解决的矛盾

1. **题源**：本地 158 条头部样本只剩 81 道 → 产出上限约 34 条合格样本。**与 pilot 200 条差约 6 倍**。路径：获取 Scale-SWE 完整数据集（此前记录约 2 万条，**本轮未核实，获取时须清点与去污染**），或引入其它许可允许的训练源。
2. **窗口**：训练方案"正式 SFT 优先争取 32K、64K 需另验"，而 80K 门的候选中 32% 超过 32K。要么做 64K/80K 显存与吞吐 smoke（5090 32GB、4B 全参，未验证），要么把长度门收回到窗口内并接受样本量再打 68 折。

## 5. 结论与建议顺序

1. **先定窗口再定量**：32K 与 64K smoke 各一次，决定长度门；样本量测算随窗口变动 ±47%。
2. **再扩题库**：没有 ≥500 道合格独立任务，pilot 无法成立；扩库后重跑家族级去污染与资格审计。
3. **pilot 目标取 200–300 条**（方案区间下沿），按上表 ≈470–700 道任务、约 3–5 亿教师 prompt token、并发 6 下半天内可采完；**先跑通，再谈 3K**。
4. 训练耗时粗估（**假设吞吐 1.5–3k token/s，未经 smoke 验证**）：1 epoch over 5.4–8.1M token ≈ 45–90 分钟——训练不是瓶颈，数据才是。

## 6. 并入 LCB(L) 池：Pilot 总量

L 池的证据全部来自项目内已有核查，无需新实验。

### 6.1 LCB(L) 池的实测锚点

| 量 | 值 | 来源 |
|---|---:|---|
| 去污染后题源上限 | **880**（release_v6 1,055 − v6 175，227 场赛、与评测 40 场不相交） | [用量复核](../../docs/2026-10-19-SFT用量复核与阶段配额.md) §3.5 |
| 首候选 final 成品率 | **96/100**，回退触发 3/100 | 同文 §2（100 题校准摘要） |
| 每条 reasoning（教师 token） | 均值 919.6 / p50 297 / p75 845；非思考部分均值 ≈140 | 同文 §4.1 |
| 每条 completion 合计 | 105,961 / 100 ≈ **1,060 教师token/条** | 同文 §2 |
| 单次调用成本假设 | 10k prompt + 3k out | [蒸馏方案](../../docs/2026-10-19-教师蒸馏SFT数据方案.md) §6 估算假设 |

注意：**L 旧导出只保留 `content`（不含 reasoning）**（用量复核 §3.4）。若要监督"短思考→交付"，须按 reasoning_content 重新导出或重采——与本工厂 SWE 侧 `reasoning_raw→reasoning_content` 是同一类修复，未做之前 L 的监督 token 只能按"答案直出 ≈150/条"计。

### 6.2 Pilot 总量：500 条 = 400 LCB + 100 SWE

配额直接采用[用量复核](../../docs/2026-10-19-SFT用量复核与阶段配额.md) §5 的首轮建议（400 L + 100 S，与训练方案 200–500 上沿一致），其中 SWE 侧 token 用**本工厂实测值**替换旧假设（旧假设 S=5k loss/12k seq；实测 10.3k/26.9k，约 2 倍）。

| 项 | LCB 400 条 | SWE 100 条 | **合计** |
|---|---:|---:|---:|
| 需要任务数（含验证 ×1.2） | ≈500（≤880 ✅） | ≈282（>81 ❌） | 782 |
| 序列 token | ≈0.8M（2k/条假设） | **2.69M（实测）** | **≈3.5M** |
| 监督 token | ≈0.40M（含短思考）/ 0.06M（仅答案） | **1.03M（实测）** | **≈1.4M / 1.1M** |
| 教师 prompt token | ≈4.3M | ≈149M | **≈153M** |
| 教师 completion | ≈0.42M | ≈3.1M | ≈3.5M |
| 教师 调用次数 | ≈429（1.03 次/条） | ≈6,400（27.4×235） | ≈6,800 |
| agent 采集时长 | 分钟级 | ≈2.5 h（并发 6） | ≈2.5 h |
| 有效 batch=16 时 update 数 | | | **≈31** |

**结构结论**：SWE 100 条贡献约 73% 监督 token、97% 教师 prompt 与几乎全部采集时长；LCB 400 条的边际成本可忽略，其价值是覆盖算法/交付行为（按 §5 配方：简单 120 / 中等 160 / 简洁思考交付 80 / 纠错停止 40）。

### 6.3 约束与退路

1. **SWE 侧仍是唯一硬缺口**：100 条需 ≈282 道任务，本地只剩 81。要么扩题库（Scale-SWE 完整集，规模未核实需清点+去污染），要么 pilot 退为 **400 L + 34 SWE ≈ 434 条**（本地可达成，SWE 覆盖降为池配方的 1/3）。
2. **L 的短思考监督未就绪**：reasoning 未保留前，L 只能按答案直出计（监督降到 0.06M），"简洁思考交付 80 条"目标暂不可交付。
3. **update 数偏少**：31 个 update 只够发现格式/mask/回归问题（用量复核 §4.2 同判断），pilot 不承诺能力证明。
4. 验证集：L 另留 100–200 题、SWE 30–50 题（家族隔离），已含在 ×1.2 内。

### 6.4 扩量参考（有收益后）

[用量复核](../../docs/2026-10-19-SFT用量复核与阶段配额.md) §5 的 700 L + 300 S 与触顶 880 L + 400 S 仍然有效；SWE 侧 300 条需 ≈847 道任务，**必须先扩库**。3,000 L + 600 S 在两侧都触及来源上限，当前不可达。
