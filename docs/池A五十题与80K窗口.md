# 池 A 五十题与 80K 窗口

日期：2026-10-21（Asia/Shanghai）。变更：长度门默认值 32,768 → **81,920（80×1024）**；新抽 50 道未跑过的题验证。

## 0. 结论

**50 题通过 25 条（50%），在 80K 窗口下 0 条超窗，全部导出；若沿用 32K，同一批会丢掉 9 条（36%）。**

| 指标 | 32K 口径（上轮 22 题） | 80K 口径（本轮 50 题） |
|---|---:|---:|
| 通过 | 14 / 22（63.6%） | 25 / 50（50%） |
| 因超窗丢弃 | **7** | **0** |
| 可导出 SFT | 7（31.8%） | **25（50%）** |
| 导出 token | 84,011 | **673,467** |
| 监督 token | 23,595（28.1%） | **256,429（38.1%）** |
| 每样本 | 12,002 / 3,371 监督 | 26,939 / 10,257 监督 |

两批题目不同，通过率不可直接比较；可比的是**窗口对"已通过样本"的浪费**：32K 丢掉一半，80K 一条不丢。

## 1. 长度分布（25 条通过样本）

| 统计 | token |
|---|---:|
| 最短 | 4,102 |
| p50 | 25,576 |
| p90 | 47,245 |
| **最长** | **79,670** |
| 超 32,768 | **9（36%）** |
| 超 81,920 | 0 |

步数：p50 = 18，最长 48 步。最长样本 79,670 离 81,920 只剩 2,250 token——**80K 也快撞线了**，再长的任务仍会被切。

## 2. 导出质量

- 25 条样本、673,467 token、监督 **256,429（38.1%）**；
- 每样本 26,939 token / 10,257 监督；
- 工具块 1,087 个（连续 tool 合并计一块）；
- `no_think = 0`（低思考生效）、`over_length = 0`。

监督占比从 28.1% 升到 38.1%，原因是这批样本的平均工具观察更少（步数 p50 18，上轮 p50 24）。

## 3. 一个必须说明的失败归因问题

50 题里 25 条 `success=false`，但其中 **1 条是基础设施失败**：

```
app-sre_qontract-reconcile_pr1008
docker.errors.APIError: 500 ... images/create?fromImage=aweaiteam%2Fscaleswe:app-sre_qontract-reconcile_pr1008
Internal Server Error ("failed to resolve reference")
```

该题 agent 跑了 35 步、产出 8,027 字符补丁，但**评测阶段拉镜像失败**，于是被记成 `success=false`。
也就是说本轮真实模型失败是 **24 条**，通过率应为 25/49（若把该题视为 infra）。

**这是工厂的计分缺陷**：`eval` 阶段的镜像/环境错误没有与模型失败分开，违反"infra 与正常失败分开统计"。建议给 evaluator 增加 infra 分类，并在结果里单列。

## 4. 与窗口决策的关系

- 80K 让"已通过样本"的浪费归零，但代价是训练序列变长（均值 26,939）；
- 最长样本已到 79,670，说明 **80K 不是安全余量，只是刚好够用**；
- 若后续仍要压长度，方向应是"导出时压缩 loss=0 的旧观察"，而不是再抬窗口。

## 6. 限制

1. 两批题集不同，通过率差异（63.6% vs 50%）不能当作口径效果。
2. 25 条失败中仅 1 条已确认是 infra，其余 24 条未逐题归因。
3. 80K 是否可训练**尚未验证**：需要训练 smoke 确认 4B 全参在 26,939 均值、79,670 峰值下的显存与吞吐。
4. 训练侧仍缺：mask 归一化损失、每条样本的 `<think>` 与监督覆盖复核。

## 7. 补查：50% 通过率为什么低（2026-10-21）

逐题拆失败模式后，原因与"预算"无关：

| 观察 | 数值 |
|---|---|
| 失败 25 条中有实质补丁 | 24（1.2k–47.6k 字符、2–8 个文件） |
| 空补丁 | 0 |
| 撞满 60 步 | 1（`pr971`，补丁 39,889，29/30 通过） |
| **只差 1–3 个断言** | **21 / 25** |
| 每个失败任务的中位"未过节点 / 通过节点" | **2 / 29** |
| 改测试文件 | 0 |

对照上轮 22 题批：8 条失败里 7 条也是"只差 ≤3 个断言"（中位 2 未过 / 90 通过）。

**结论：通过率低不是模型不干活，而是判定是全或无。**模型平均落在"29 个节点过、2 个节点不过"的位置，
按严格全门判就是失败；按"几乎正确"看则是高完成度。50 题批的题集里 `app-sre/qontract-reconcile` 与
`beetbox/beets` 占比更高，边界条件更难，于是同样"差 1–3 个断言"的样本更容易跨不过线。

由此得到两条可执行结论：

1. **池 A 用严格全门**不变（SFT 只吃全过样本）；
2. **这些"差 1–3 个断言"的轨迹正是池 B 的原料**——失败轮（含真实 pytest 输出）与后续修正轮配对，
   监督只算修正轮。当前 25 条失败里 21 条可直接作为失败轮候选，不需要重新采集。
